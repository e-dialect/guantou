# ADR-0006：以词条、分义和录音多对多关系重建方言资料模型

## Status

Accepted。锁仓前评审已通过；V2 领域模型从迁移 `0020_entry_recording_v2_domain` 开始分阶段实施，旧模型在客户端和导入器完成切换前继续并存。

## Context

现有模型把 `Can` 定义为录音，把 `Nameplate` 定义为一条录音上的资料主张。因此 Nameplate 必须依附 Can：没有录音的旧词无法成为 Nameplate；同一个旧词有多条录音时，导入器又会为每条录音各建一张 Nameplate。实际产品语义正好相反：用户所说的“铭牌”就是可以独立存在和检索的词条，一条词条可以没有录音，也可以由多个地区、多位说话人的录音提供证据；同一段例句也可能涉及多个词条。

普通母语者往往只知道“这个说法表示害怕”，未必知道正字、IPA 或来源。系统必须允许这种粗略记录公开成为可整理的初稿，同时让方言爱好者和整理员逐步补全写法、分义、读音和证据，且不覆盖最初贡献者的原话。

同一写法也不能等于同一词条。“银行”的“行”和“行走”的“行”应当分开；“走”在一些地区表示步行，在莆仙等方言中可以表示奔跑，也不能仅因字形相同而混为一条。另一方面，同一词在不同地区的系统性音变、文白异读或多种书写方式又不应被机械拆散。

旧库只读审计显示：6,133 个 `word_word` 中4,969个没有录音；1,368条录音只覆盖1,164个旧词；99种相同写法涉及203条独立旧记录；307条定义有①②等分义线索。迁移不能继续以录音数量决定词条数量，也不能按写法自动合并。

## Decision

### 1. 领域词汇

新代码、API 和用户文案使用以下明确名称：

| 模型 | 用户含义 | 核心职责 |
| --- | --- | --- |
| `Entry` | 词条 | 表示同一个词及其读音身份，可独立于录音存在 |
| `EntrySense` | 分义 | 保存词条下的编号义、用法和例句 |
| `WritingForm` | 写法 | 保存正字、俗写、借字、拟音、罗马字等形式 |
| `EntryWriting` | 词条写法关系 | 说明主写法、其他写法或争议写法 |
| `Concept` | 概念 | 关联表达同一抽象意义的不同词条，不直接充当词条 |
| `PronunciationVariant` | 地区读音 | 保存词条在某方言节点的读音、文白异读和来源状态 |
| `Recording` | 录音 | 保存音频、说话者关系、使用地区、类型和原始大意 |
| `RecordingEntryLink` | 录音词条关系 | 说明一段录音主要展示、提及或可能解释为哪个词条 |
| `Source` / `EvidenceRecord` | 来源与证据 | 保存用户原话或文献著录的不可覆写快照 |
| `UsageAttestation` | 本地使用确认 | 表达“我这里也这么说”，与正确性投票分开 |

`Can`、`Nameplate`、`Flavor`、`Package` 不再作为新领域 API 的正式名称。“罐头、盒子”等意象可以保留在品牌视觉和运营文案中，但不承担数据模型含义。

### 2. 词条与分义边界

Entry 表示一个可独立辨识的词及其读音身份，而不是单纯字形，也不是把所有相近意思聚成一条。

- 同形但核心意义、词源或意义绑定的读音明显不同，建立不同 Entry。
- 同一词在不同地区的系统性语音变化保留在同一 Entry 的 PronunciationVariant 下。
- 文白异读、代际差异和有证据的竞争读音可以并存，不因字符串不同自动拆词条。
- 同一读音身份下彼此相关的编号义可以成为多个 EntrySense；整理员仍可在证据出现后拆分 Entry。
- 同一 Entry 可以关联多个 WritingForm；同一 WritingForm 也可以关联多个 Entry。

搜索同一写法时必须返回多个独立 Entry 卡片，以主要分义和读音帮助用户消歧，不能只返回一个“写法”对象再把不同词埋在二级页面。

### 3. 概念关联

Concept 是跨写法、跨地区检索相近表达的内部语义节点，与 EntrySense 建立关系。普通话名称只是解释 Concept 的界面语言，不是判断方言词义的权威。

示例：

| 词条 | 分义 | 概念关系 |
| --- | --- | --- |
| 行¹ | 行走、运行等相关义 | WALK、MOVE |
| 行² | 行业、行号、银行相关义 | TRADE、BUSINESS |
| 走¹ | 在适用地区表示步行 | WALK |
| 走² | 在莆仙等适用地区表示奔跑 | RUN |
| 跑¹ | 在适用地区表示奔跑 | RUN |

行¹和走¹仍是不同词条，只因相近分义关联到 WALK；走²和跑¹同理关联到 RUN。Concept 只帮助查找和比较，不触发 Entry 合并。

### 4. 录音与词条多对多

Recording 与 Entry 通过 RecordingEntryLink 多对多关联。关系角色固定为：

- `primary`：录音主要展示的词条和可选分义；每段录音最多一个已接受的 primary。
- `mention`：例句中出现的其他词条。
- `competing`：对录音存在另一种可追溯解释。

录制者创建录音时选择或生成的 primary 立即生效。其他用户给别人的录音增加关系时先形成建议，只有录制者或该使用地区范围内的地区整理员可以确认。调整 primary 必须保留旧选择、操作者、理由和时间。

Recording 只记录“这个说法在哪个方言范围使用”，不记录设备所在位置、经纬度或后台定位。录音可以是词、短语或例句；例句提交时确定主要表达，句中其他词可以稍后补充。

普通录音提交的最低要求是音频、使用地区和大意。写法和专业标音可空；服务端事务化创建 Recording、初稿 Entry、初始 EntrySense、用户自述 EvidenceRecord 和 primary 关系。没有录音的纯文字词条必须提供使用地区、大意和至少一种可检索形式。

### 5. 原始证据、修订与拆合

EvidenceRecord 保存来源中的原样写法、原释义、原转写、出处位置和贡献者表述。已经公开或被引用的证据不得原地改写；专业整理修改规范 Entry 或 EntrySense，并保留修订记录。

- 同一核心主张的补全进入 `EntryRevision`。
- 实质不同的解释建立竞争 Entry。
- 合并采用可撤销的 canonical/redirect 关系，不删除旧 Entry、来源或旧 ID。
- 拆分记录被移动的分义、证据、读音和录音关系，允许按操作记录撤销。
- 现有“支持数自动提高权重并选主”的行为废止；热度不能决定写法或读音正确性。

作者可以选择来源类型，但不能自行选择“官方认证”等证据等级。词条、地区读音和录音关系各自拥有独立审核状态，不能用一个全局状态宣称整条跨地区资料已经绝对正确。

### 6. 本地使用确认

UsageAttestation 表达某用户认为某 Entry 在某 Dialect 范围内使用：

- 同一用户、Entry、Dialect 最多一条有效确认。
- 用户可以撤回或继续补录自己的版本。
- 确认人数和公开录音数分别统计。
- UsageAttestation 不改变主写法、主读音或审核状态。

### 7. 方言范围与整理权限

Dialect 继续是一棵按需展开的方言关系树，父节点和叶节点都允许成为使用范围。选择 `闽.莆仙` 只表示已知资料适用于莆仙方言范围，不能推断其适用于每一个下级节点。

权限分为：

- `lexical_curator`，用户称“词条整理员”，审核写法、分义、概念、修订和词条拆合。
- `regional_curator`，用户称“地区整理员”，审核获授权 Dialect 节点及其后代的使用范围、读音和录音关系。

用户通过贡献样例和申请说明申请；由现有管理员人工授予，默认一年复核，可提前撤销。无整理员地区的内容仍可公开，但显示“待证”。所有审核决定公开显示账号、职责范围、理由和时间。

### 8. 旧库迁移

- 每个 `word_word.id` 先创建一个可追溯初始 Entry，无论是否有录音。
- 每个 `word_pronunciation.id` 只创建一个 Recording，并关联回来源 Entry。
- 相同写法的不同旧记录保持独立，只生成可能重复候选。
- ①②等编号解析为 `SenseSplitProposal`；人工决定转成多个 EntrySense，还是拆成多个 Entry。
- 同地多读音只提高拆词条复核优先级，不自动裁决。
- 旧标准 IPA、拼音按既定规则映射到 `闽.莆仙.莆田.城里`。
- 旧词条与录音的可见性分别保留，隐藏内容不得自动公开。
- 迁移账本继续记录源系统、表、旧 ID、目标对象和指纹，并保证重复导入幂等。

## Public interface consequences

新接口以 `/entries/`、`/entry-senses/`、`/recordings/`、`/recording-entry-links/`、`/usage-attestations/` 和 `/curation/` 为主要资源。搜索首先返回 Entry，并允许按使用地区、是否有录音、写法类型、来源、状态、IPA 和罗马字筛选。

前端完成切换后删除 `/cans/`、`/nameplates/` 等旧领域契约。项目没有外部 API 消费者，不维护长期双版本；实施期间只允许为保证逐提交可运行而短暂并存。

## Consequences

### Positive

- 无录音词条和一词多录音都得到自然表达。
- 普通用户可以低门槛记录，专业用户可以在不抹除原话的前提下整理。
- 同形异义、同义异词、地区音变、文白异读和例句多词关联有明确边界。
- 人气反馈、资料证据和整理决定不再混为同一种“支持”。
- 词条与地区的审核责任可按知识范围下放。

### Negative

- Entry、EntrySense、Concept、PronunciationVariant 和 EvidenceRecord 的查询与表单比当前模型复杂。
- 拆分和合并必须有专用服务与审计记录，不能依赖普通 CRUD。
- 旧界面和旧 API 需要协调切换，无法只改模型而保持现有心智模型。

## Superseded decisions

本 ADR 实施后，将取代 ADR-0001 中 Pronunciation 依靠 Nameplate 获得 Can 证据的关系，以及 ADR-0002 中“Nameplate 必须属于一个 Can”的核心决定。Dialect 树、规范读音与原始证据分离、稳定来源和修订历史等原则继续保留。账号删除后的核心资料保留与匿名化继续遵循 ADR-0004，并扩展到 Entry、EvidenceRecord 和 Recording。
