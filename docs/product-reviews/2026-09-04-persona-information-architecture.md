# 乡声集盒多用户视角与信息架构评审

## 评审目标

本轮优先检查功能、信息层级、数据流转和跨用户协作，不重新设计颜色、字体、插画或卡片风格。已有和在途的界面美化成果应在锁仓后复用；本方案只决定页面需要让用户看见什么、先做什么，以及专业信息何时展开。

产品的共同主路径是：

```text
听见一种说法
→ 看懂它的大意和使用范围
→ 找到对应词条及地区读音
→ 确认“我这里也这么说”或录下本地版本
→ 爱好者补写法、分义、标音和来源
→ 整理员按职责范围校对并保留历史
```

领域模型与迁移边界见 [ADR-0006](../adr/0006-entry-sense-recording-domain.md)，旧库数量与异常见 [旧库词条审计基线](../audits/2026-09-04-legacy-lexicon-audit.md)。

## 当前体验检查

### 已有基础

- 首页已经具备连续播放和社交内容流的雏形，适合承担长期收听入口。
- `Package` 与 `Flavor` 在数据库层面可以表达同一写法关联多个义项；写法详情也会列出关联义项。
- 录音和铭牌创建页已经开始使用方言树级联选择，并提供默认和最近使用快捷项。
- 系统已有搜索、地区树、货架、录音挑战、评论、收藏和访问审计等基础能力。

### 关键断点

- 首页一段录音同时陈列多张铭牌和多组操作，用户需要先理解产品术语才能知道该做什么。
- 搜索把写法、义项、铭牌和录音并列展示。“行走的行”和“银行的行”虽然可以在底层建成不同 Flavor，用户却不能直接得到两个清晰独立的词条结果。
- Nameplate 必须依附 Can，导致无录音旧词没有用户所理解的“词条”；同一旧词的多条录音又会产生多张重复铭牌。
- “支持铭牌”既像使用确认又参与主铭牌选举，把地区经验、人气和正确性混在一起。
- `正品认证`、`官方认证` 等文案容易把有限范围的整理判断包装成绝对结论。
- 新用户引导、关注地区和个人资料仍使用长列表或平铺选择；多个普通页面直接显示 `闽.莆仙.莆田.城里`。
- “我的”页面同时承担个人资料和内容入口，不能简单改成“我的贡献”；整理入口也需要与系统后台分开。

## 用户视角

### 1. 普通方言母语者

典型认识是“会说，但不知道怎么写”，甚至以为方言没有对应汉字。用户能可靠提供的是声音、大意和大致使用范围，不应先被要求判断正字、IPA、文白读或证据等级。

需要的体验：

- 先听和录，再逐步解释资料如何形成词条。
- 录音最低只填“使用地区”和“这句话大概什么意思”。
- 明确告诉用户：“不知道汉字也可以；可以先用自己习惯的字、拟音或罗马字，之后由大家补充。”
- “我这里也这么说”必须绑定用户选择的方言范围，而不是对全站正确性投票。
- 不清楚村镇差异时允许停在“莆仙方言”，之后再由本人或整理员补充得更具体。

成功标准：用户无需解释即可从播放完成一次地区确认或录音提交，且不会因不知道写法中途退出。

### 2. 有一定水平的方言爱好者

这类用户能够辨别同形异义、正俗写、不同读音和来源可靠性，但不一定具有整个方言区的知识。

需要的体验：

- 搜索首先返回独立词条；相同写法以释义和读音消歧。
- 高级筛选支持使用地区、是否有录音、写法类型、来源类型、状态、IPA 和罗马字。
- 词条详情能查看原始证据、分义、各地读音、录音、竞争解释和修订历史。
- 同一主张的完善提交修订；实质不同的解释另立竞争词条。
- 系统可以提示相似项和拆分候选，但不能替用户作语言学裁决。

成功标准：用户能找到“同写法不同词”的所有候选，说明自己的修改依据，并确认原来源没有被覆盖。

### 3. 学习者和非本地用户

这类用户主要想知道“是什么意思、哪里这样说、怎么读”，不应在进入详情时面对完整考据表单。

需要的体验：

- 默认先显示自然写法、白话释义、自然地区名称和播放按钮。
- 同一词条的地区读音以可比较列表呈现，并允许接着播放。
- IPA、罗马字、来源、异议和修订历史放在“考据与来源”展开区。
- 无录音词条仍可查到，显示“待补音”和清晰的补录入口。

成功标准：用户不切换所谓“专业模式”也能完成一次理解和地区比较，需要时才在同一页面展开专业资料。

### 4. 词条整理员和地区整理员

整理员的价值是说明证据和限定适用范围，不是获得全站裁判身份。

词条整理员负责：

- 写法关系、分义、概念关联和规范释义。
- 修订、同形词拆分、重复候选合并和撤销。

地区整理员负责获授权方言节点及其后代：

- 使用范围、地区读音和录音词条关系。
- 第三方关联建议、宽泛地区细化和地区分歧。

需要的体验：

- 待办按“影响大、资料多、存在冲突、长时间未处理”排序。
- 对比原证据和建议结果后，以理由接受、拒绝或要求补充。
- 所有决定公开显示账号、职责范围、理由和时间，并可撤销。
- 没有本地整理员时，内容保持公开并显示“待证”，不交给全局管理员冒充地方判断。

成功标准：整理员能在不打开 Django 后台的情况下闭合日常审核；后台只负责授权、封禁和异常修复。

### 5. 运营者和维护者

长期活跃不能只依赖点赞和评论。产品应把消费行为转成可验证的小贡献，并让资料稀少地区得到曝光。

需要的体验：

- 推荐优先用户关注或选择的方言支系，同时保留适度跨地区探索。
- 在相关录音之后插入“你那里怎么说”的地区对比接龙。
- 录音挑战按地区、概念和待补音词条组织。
- 观察播放完成、打开词条、本地确认、开始录音、提交录音、修订处理和地区审核积压。
- 点赞与评论只反映社交互动，不进入词条可信度。

成功标准：能够衡量“听→确认→录制→整理”的完整漏斗，而不是只看播放量和点赞数。

## 一级信息架构

一级视觉标签采用 `听 / 查 / 录 / 我`。图标的无障碍名称和页面标题使用“听录音、查词条、录一段、我的账户”，避免单字脱离图标后失去含义。

### 听

每屏以一段 Recording 为主，不同时平铺多张完整词条卡。首屏只需要：

1. 播放与进度。
2. 主要 Entry 的写法或“表示……的说法”。
3. 白话大意和自然地区标签。
4. 查看词条、“我这里也这么说”和“录下我这里的版本”。
5. 收起的点赞、评论和分享。

录制者最初选择主要词条；对应地区整理员可以有理由地调整。其他解释保留在词条入口或“存在不同解释”提示中，不以多卡片争夺首屏。

### 查

默认是一个搜索框和词条优先结果；下方提供地区、主题、接龙和集盒入口。搜索相同写法时先按 WritingForm 聚合视觉标题，再列出不同 Entry 卡片，但每张卡拥有独立 ID 和详情页。

筛选抽屉包含：

- 使用地区，可选精确节点或包含后代。
- 有录音、待补音或不限。
- 正字、俗写、借字、拟音、罗马字等写法类型。
- 社区自述、口述、田野、书籍、论文、档案、网页等来源类型。
- 词条 `初稿 / 已校 / 分歧` 和地区资料 `待证 / 已核 / 分歧`。
- IPA、罗马字、文读、白读等专业条件。

无录音 Entry 与有录音 Entry 使用同一搜索排序基础，不能因录音数为零从结果中消失。

### 录

默认流程只包含：

1. 录制或重录音频。
2. 选择使用地区。
3. 填写大意，例如“表示害怕的意思”。
4. 提交。

“想多说一点”展开区允许补充：

- 自己认为的写法以及“可能不准确”。
- 词、短语或例句类型。
- 例句中的主要表达和其他表达。
- 自己会读但不会写、长辈口述、田野记录或文献来源。
- IPA、罗马字、文白读和用法说明。

系统在提交后说明资料流转：“已经记为初稿；其他人可以补写法和读音，原始录音与说明会一直保留。”

纯文字创建放在高级入口，最低要求为使用地区、大意和至少一种可搜索形式，不要求有录音。

### 我

“我”保持账户中心职责，按以下区块排列：

1. 个人资料：头像、昵称、公开主页和资料编辑。
2. 我的范围：默认方言、关注方言和最近使用。
3. 我的内容：录音、词条、补证、修订和草稿。
4. 收藏与关注：词条、集盒、地区和用户。
5. 贡献履历：按贡献类型和覆盖地区展示，不把积分称号当作专业资格。
6. 协作与整理：普通用户看到申请入口；已授权者看到“管理与审核”和待办数。
7. 账号与隐私：登录方式、安全、录音授权、内容撤回和注销。

Django 系统后台不在客户端菜单中；它只面向全局运维人员。

## 词条详情的渐进层级

词条详情按理解顺序排列：

1. 主写法、主要分义、短状态。
2. 各地区读音与可播放录音。
3. “我这里也这么说”和补录入口。
4. 其他写法和相关概念词条。
5. 例句和用法。
6. 可展开的“考据与来源”：IPA、罗马字、来源原文、竞争意见、审核记录和修订历史。

同形词必须在搜索和详情首屏消歧。例如搜索“行”时，“行走相关”和“行业、行号相关”是两张独立 Entry 卡；它们共享 WritingForm 字符串，但不共享词条状态和读音列表。

## 使用地区组件

所有录入、注册引导、个人资料、关注和搜索筛选统一复用一个逐级选择器：

- 从当前层进入下一层，每层都有“就选这里”。
- 支持搜索、默认地区和最近使用。
- 父节点和叶节点都可提交。
- 选择父节点时提示可以以后补得更具体，不把“不清楚”当成错误。

普通页面统一使用自然名称：

- `闽.莆仙` → “莆仙方言”。
- `闽.莆仙.莆田.城里` → 卡片“莆仙方言 · 城里”。
- 详情完整路径为“闽语 › 莆仙方言 › 莆田 › 城里”。

内部 `qualified_code` 只用于稳定解析、历史别名和管理界面。选择莆仙父节点的资料只代表已知到莆仙范围；筛选城里时不能把宽泛的莆仙资料冒充为城里资料。

## 状态与信任表达

前台短状态保持简洁：

- 词条：`初稿 / 已校 / 分歧`。
- 地区资料：`待证 / 已核 / 分歧`。

详情中的完整说明必须回答：谁、以什么角色、在什么范围、基于什么理由、何时作出判断。作者不能自行选择“官方认证”。地区确认数、录音数、文献来源数和社交点赞数分别展示，不合成为单一权重。

## 跨端与隐私

- 不获取设备位置，不保存经纬度，不申请微信位置和后台 location 权限。
- 微信与 H5 共用业务页面，通过集中能力矩阵处理录音、播放、分享和审核差异。
- 核心浏览、搜索、播放、录制、本地确认和个人资料尽量在微信开放；受平台限制的能力由编译能力与服务端开关共同关闭。
- 第一方产品事件不记录搜索原文、录音内容或位置；原始事件保留90天，之后只保留日汇总。
- 首次录音取得版本化授权，之后显示简短提醒；明确说话者是本人、已获授权的他人或档案来源。

## 验收任务

### 普通母语者

- 听懂一条录音并找到白话大意。
- 在不知道汉字和 IPA 的情况下完成录音、大意和莆仙方言范围提交。
- 知道提交后仍可由他人补写法，且自己的原话不会被覆盖。

### 方言爱好者

- 搜索“行”并打开两个独立词条。
- 找到“走＝步行”和“走＝奔跑”，确认它们分别关联 WALK 和 RUN。
- 按地区和读音筛选，查看来源并提交有理由的修订。

### 学习者

- 不展开专业区即可完成释义理解、播放和地区比较。
- 需要时在同一详情页查看 IPA、来源和分歧。

### 整理员

- 从“我”进入待办，确认一条录音关系和一条分义建议。
- 在权限范围外不能作出地区审核决定。
- 撤销一次决定后，原证据、旧状态和理由仍可追溯。

### 数据迁移

- 6,133 个旧词先形成6,133个可追溯初始 Entry，人工拆分后总数可以增加。
- 1,368 条旧录音只形成1,368条 Recording 和1,368条初始 primary 关系。
- 4,969 个无录音 Entry 可搜索并显示“待补音”。
- 重复写法、编号定义和多读音只生成候选，不自动合并或拆分。

## 实施边界

锁仓前只发布本评审材料、领域 ADR 和只读审计工具，不修改页面或运行时模型。评审 PR 合并并收到明确锁仓通知后，才在 `main` 上按模型、导入、API、前端、地区、治理、平台和旧契约清理分段提交。每次提交保持可运行并通过相称测试；若锁仓期间远端 `main` 出现意外更新，停止并协调，不覆盖其他贡献者工作。
