# 乡声集盒产品设计文档

**文档状态：** 首期开发框架
**更新日期：** 2026-08-02

乡声集盒是从旧兴化语记/方言词典系统升级而来的多方言语音档案库。首期目标不是从零发明一套产品，而是在旧系统的词典、发音、搜索、登录和审核经验上，重建为“录音优先 + 铭牌共识 + 全国多方言检索”的新模型。

## 0. 文档来源与优先级

本文档是当前产品与实现的源头。旧讨论稿可以补充页面布局、状态和交互细节，但不能覆盖本文档里的模型关系和术语定义。

可参考的旧稿已归档到 `docs/references/`：

- `visual-dictionary-v1.md`：早期 6 个核心页面的文字交互说明。
- `frontend-interaction-v2.html`：带手机线框预览的前端交互稿，可直接用浏览器打开查看。
- `product-runtime-logic-social-v1.md`：旧版“方言微博/社区玩法”运行逻辑，用于远期传播层参考。

遇到冲突时按以下规则处理：

- 旧稿里的“方言罐头”按当前品牌“乡声集盒”处理。
- 旧稿里的“货架”按用户文案“集盒”处理，代码仍是 `Shelf`。
- 旧稿里的“风味”按用户文案“义项”处理，代码仍是 `Flavor`。
- 旧稿里的“词条详情”不是一个单一新模型，应拆到 `Flavor` 详情、`Package` 详情和 `Can` 详情分别落地。
- 旧稿里的“采集表”首期优先解释为“为已有义项补录音”；批量词表采集作为后续增强，不阻塞 v1。
- 旧稿里的“博文/发帖/微博流”只能作为未来社区层，不能替代 v1 的罐头、义项、写法、铭牌主线。

## 1. 术语与命名

| 术语 | 代码模型 | 用户文案 | 说明 |
| --- | --- | --- | --- |
| 产品品牌 | - | 乡声集盒 | 应用名称，可继续调整，不影响模型/API |
| 核心动作 | - | 装罐 | 用户录入一段方言语音 |
| 录音实体 | `Can` | 罐头 | 一条具体方言录音，是数据原子 |
| 用户判断 | `Nameplate` | 铭牌 | 某个用户对某条罐头的写法、义项、释义、来源判断 |
| 语义节点 | `Flavor` | 义项 | 解决“同字不同义”和跨地区同义检索 |
| 文字入口 | `Package` | 写法 | 用户可能搜索或书写出来的字面形式 |
| 主题集合 | `Shelf` | 集盒/盒子 | 按主题组织义项或罐头，代码暂不改名 |

代码命名保持 `Can / Nameplate / Flavor / Package / Shelf` 稳定。不要回退到旧系统的 `Word/List` 命名，也不要因为品牌文案变化频繁迁移模型、API 或路由。

## 2. 核心模型关系

固定关系：

```text
Can 1 - N Nameplate
Nameplate -> Flavor
Nameplate -> Package
Flavor N - N Package
Shelf N - N Flavor / Can
```

`Flavor` 负责义项，例如“月亮”“银行机构”“行走动作”。它让用户可以快速检索“全国各地方言里月亮怎么说”。

`Package` 负责写法入口，例如“行”“杀”“刣”“月光”“月娘”。它让用户搜索同一个字面形式时，能够看到不同义项。

`Nameplate` 是具体到某条录音的用户主张。它同时指向一个 `Flavor` 和一个 `Package`，并保存释义、证据来源、权重和是否主铭牌。

示例：

```text
Flavor「月亮」
├─ Package「月亮」
├─ Package「月光」
├─ Package「月娘」
└─ 通过 Nameplate 连接到全国各地方言录音 Can
```

```text
Can #1 某地方言录音
├─ Nameplate A：Package「杀」 + Flavor「宰杀」 + 注解甲
├─ Nameplate B：Package「刣」 + Flavor「宰杀」 + 注解乙
└─ Nameplate C：Package「杀」 + Flavor「打/伤害」 + 注解丙
```

首期暂不解决 `Flavor` 标准化难题，只允许人工创建/选择义项。后续再做合并建议、同义归并、AI 推荐和管理员审核。

## 3. 旧系统参考与迁移原则

旧仓库是参考源，不作为运行时依赖引入：

- `hinghwa-dict-uni-app/src/pages/search.vue`：搜索页、搜索历史、搜索类型切换。
- `hinghwa-dict-uni-app/src/pages/words`：词条详情、发音列表、词典页面结构。
- `hinghwa-dict-uni-app/src/services/word.js`：旧词条搜索和批量获取 service。
- `hinghwa-dict-uni-app/src/utils/audio.js`：旧音频播放提示和错误处理。
- `hinghwa-dict-backend/hinghwa-dict-backend/word`：旧 `Word / Pronunciation / Character / List / Application` 模型与接口。
- `hinghwa-dict-backend/hinghwa-dict-backend/user`：旧用户、登录、资料逻辑。
- `hinghwa-dict-web/src/views/SearchResult.vue`：桌面端搜索结果组织。
- `hinghwa-dict-web/src/views/Words`：桌面端词条详情展示。

旧模型到新模型的映射：

| 旧系统 | 新系统 | 迁移说明 |
| --- | --- | --- |
| `Word` | `Flavor + Package + Nameplate` | 旧词条里“字面词形”和“义项”混在一起，新系统拆开 |
| `Pronunciation` | `Can + FlavorVariant` | 旧发音成为录音罐头，并可挂到某个义项变体 |
| `List` | `Shelf` | 旧词单迁移为主题集盒 |
| `Application` | 后续审核/修订申请 | 首期不恢复完整申请系统，只保留治理参考 |
| `Character` | 材料/检索参考 | 单字不作为新系统核心一等实体 |

迁移时可以借鉴旧字段、边界处理和交互，但必须按当前 Vue3/Vite/DRF 与新模型重新实现。

## 4. 核心页面与首期范围

首期产品先完成“像词典一样可查、可录、可校验”的基础闭环。社区玩法可以增强留存和传播，但必须建立在 `Can（罐头）` 之上，而不是把“发博文”变成新的数据原子。

### 首页

- 品牌展示“乡声集盒”。
- 主要入口：搜索、集盒、装罐、图鉴、我的。
- 第一屏优先展示品牌、搜索入口、一个“随机/精选罐头”或最近罐头高亮信息，再展示快捷入口和最近罐头列表。
- 最近罐头列表按时间倒序展示，卡片显示主铭牌写法、义项/普通话概念、方言点、铭牌数和状态。
- “采集表”可以作为装罐的子入口或后续快捷入口，不要求进入首期底部主导航。

### 装罐页

两种模式：

1. 自由装罐：用户填写普通话概念、方言点、录音，可选候选写法、释义、写法类型、来源说明。
2. 为已有义项补录音：从 `Flavor` 详情进入，锁定义项，只选择方言点并录音，提交后仍创建 `Can`。

自由装罐的必填项为普通话概念、方言点、录音。不会写正字也可以先提交，后续由社区贴铭牌。

装罐交互应保持低门槛：

- 模式切换用清晰的分段控件，默认进入自由装罐。
- 必填区只放普通话概念、方言点和录音；候选写法、释义、写法类型、来源说明放在选填折叠区。
- 录音区同时支持按住录音和本地音频上传。
- 录音权限被拒时提示需要麦克风权限；提交失败时尽量保留已填表单，并进入本地草稿能力。
- 提交成功后跳转罐头详情或义项详情，并给出状态反馈。

### 罐头详情页

- 主要区展示主铭牌、普通话概念、方言点、录音者和播放按钮。
- 铭牌区展示所有用户主张；支持数最高的铭牌成为主铭牌。
- 同一录音可以有多个铭牌；写法相同但释义、义项或来源不同，也可以作为不同铭牌存在。
- 主铭牌卡片应比普通铭牌更突出，但文案避免暗示“唯一正确答案”。
- 铭牌支持按钮使用“支持”，不要使用“点赞”或“反对/踩”。

### 图鉴与义项详情

- 图鉴按 `Flavor` 组织，展示“同一个意思在不同地方怎么说”。
- 义项详情显示关联写法、方言变体、相关罐头。
- 例如 `Flavor=月亮` 可以检索全国各地方言里的月亮说法。
- 义项详情可以借鉴旧词典式页面的紧凑信息结构：义项标题、关联写法、方言点统计、相关罐头、补录音入口。
- 如果后续加入例句，例句属于义项或铭牌的补充材料，不改变 `Flavor / Package / Nameplate` 的基本关系。

### 写法详情

- 写法详情按 `Package` 组织，展示一个写法可能关联的多个义项。
- 例如 `Package=行` 下区分“银行机构”“行走动作”“可以/好”等义项。
- 写法详情的核心是消歧，不要把某个写法直接固定为唯一义项。
- 页面应把每个关联义项作为可点击入口，并显示该义项下已有多少罐头、多少方言点。

### 集盒

- 集盒是主题集合，内部仍使用 `Shelf`。
- 用户界面优先使用“集盒/盒子”，减少“货架”意象。
- 集盒可以收纳义项或罐头。

### 搜索

首期先实现传统单框搜索，聚合义项、写法、罐头。搜索历史、热门搜索、实时联想可以逐步增强。

搜索聚焦态可参考旧前端交互稿：

- 用户点击首页搜索框后，隐藏首页内容和菜单干扰，只保留搜索输入、返回/取消和搜索辅助内容。
- 输入为空时展示搜索历史、热门搜索或推荐义项。
- 输入关键词后同时展示义项、写法和罐头结果；结果项必须清楚标明类型。
- 点击返回或取消时恢复进入搜索前的页面。

### 后续扩展

- 乡音留言：围绕罐头的轻量评论和点赞。
- 草稿箱：提交失败时保存本地草稿。
- 方言圈：圈子、加入退出、圈内罐头列表。
- 铭牌支持唯一性：每人对每张铭牌只能支持一次。
- 争议态：最高两张铭牌支持数接近时标记为 `disputed`。

### 远期社区玩法层

旧运行逻辑稿里的“方言微博”方向可以作为远期增长与娱乐层，但进入路线图时要降级为 `Can` 之上的功能：

- 信息流：展示同方言、关注、推荐或同城的公开罐头动态，动态卡片以罐头播放为核心。
- 发帖/博文：未来可以作为罐头的包装与传播，不应替代装罐流程；无罐头的纯文本发布不是近期目标。
- 用同款：引用已有 `Can` 生成自己的表达或动态，是比转发更贴近方言语音的传播机制。
- 罐头库：用户管理原创、收藏、草稿和可复用罐头素材。
- 发现与话题：热罐头、热义项、今日方言词和方言挑战可以把词典内容带回社区消费。
- 消息与关注：点赞、评论、支持铭牌、用同款、审核结果等通知可以逐步补齐。
- 方言圈：作为归属和主题讨论空间，但圈内内容仍优先围绕罐头、义项和集盒组织。

这些能力的优先级低于模型、搜索、装罐、详情页和旧词典数据迁移。写 issue 时应明确标注远期 milestone，避免新手把“微博产品”当成 v1 主线。

建议 milestone 分层：

- 每个 milestone 尽量控制在 5 人一周左右能交付的范围。
- `v0.0.1`：装罐基础闭环，包括自由装罐、补录音、录音、试听重录、上传和选填折叠。
- `v0.0.2`：词典检索闭环，包括首页、搜索聚焦、热门/联想、搜索聚合、铭牌机制和旧词典迁移样例。
- `v0.0.3 登录与方言身份`：登录/注册、游客拦截回跳、主方言选择、老用户补选和基础权限。
- `v0.0.4 个人罐头资产`：罐头库、草稿箱、原创/收藏/草稿列表。罐头库属于词典资料库能力，不归入社区娱乐层。
- `v0.0.5 轻互动与通知`：罐头详情留言、点赞/支持类反馈、基础通知和审核提醒。
- `v0.0.6 方言圈与发现`：方言圈、热罐头、热义项、今日方言词、方言挑战和发现页雏形。
- `v0.0.7 社区传播实验`：用同款、同方言信息流、推荐/推送实验。到这一阶段才开始明显借鉴“方言微博”玩法。

## 5. 状态与边界

`Can.status` 沿用当前代码：

| 状态 | 含义 |
| --- | --- |
| `unlabeled` | 无铭牌 |
| `pending` | 已有铭牌，等待社区或管理员校验 |
| `tentative` | 社区暂定 |
| `verified` | 已认证 |
| `disputed` | 存在争议 |
| `rejected` | 已驳回 |

首期创建罐头后默认为 `unlabeled`。贴第一张铭牌后进入 `pending`。更复杂的状态流转后续由专门 issue 落地。

页面状态要求：

- 空态要给出下一步动作，例如“来录第一罐”“去装罐”“为这个义项补录音”。
- 列表页加载时用骨架屏或稳定占位，避免内容跳动。
- 音频上传中要展示进度或明确的上传状态，并避免用户误以为已经完成。
- 网络错误使用顶部 toast 或页面内错误区，文案保持可操作。
- 401 未登录优先跳转登录页，登录后回到原页面。

## 6. Issue 编写标准

每个 issue 都按“小白可执行”模板写：

1. 背景：为什么做，解决什么用户问题。
2. 目标：完成后用户能做什么。
3. 概念解释：涉及 `Can / Nameplate / Flavor / Package / Shelf` 时必须写中文别名。
4. 旧代码参考：列出旧仓库具体路径。
5. 视觉/交互参考：如涉及页面 UI，列出 `docs/references/` 里的旧稿路径，并说明哪些内容可参考、哪些旧概念要替换。
6. 当前代码入口：列出新仓库建议阅读文件。
7. 实现步骤：写成明确的 1、2、3，不跳步。
8. 数据/API：说明字段名、请求示例、响应示例。
9. 验收标准：用 checklist。
10. 测试方式：列具体命令和手测路径。
11. 非目标：说明本 issue 不做什么，避免越做越大。

父 issue 管方向，子 issue 管单一交付。每个子 issue 尽量控制在 0.5-2 人日。

## 7. 验收样例

首期迁移和模型关系至少覆盖三类样例：

- “月亮”：同一个义项在全国多个地方怎么说。
- “行”：同一个写法对应多个不同义项。
- “杀/刣”：同一条录音存在不同写法或不同注解的铭牌争议。
