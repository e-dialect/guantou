# 乡声集盒产品设计文档

**文档状态：** 首期开发框架
**更新日期：** 2026-08-02

乡声集盒是从旧兴化语记/方言词典系统升级而来的多方言语音档案库。首期目标不是从零发明一套产品，而是在旧系统的词典、发音、搜索、登录和审核经验上，重建为“录音优先 + 铭牌共识 + 全国多方言检索”的新模型。

## 1. 术语与命名

| 术语 | 代码模型 | 用户文案 | 说明 |
| --- | --- | --- | --- |
| 产品品牌 | - | 乡声集盒 | 应用名称，可继续调整，不影响模型/API |
| 核心动作 | - | 装罐 | 用户录入一段方言语音 |
| 录音实体 | `Can` | 罐头 | 一条具体方言录音，是数据原子 |
| 用户判断 | `Nameplate` | 铭牌 | 某个用户对某条罐头的写法、义项、释义、来源判断 |
| 语义节点 | `Flavor` | 义项 | 解决“同字不同义”和跨地区同义检索 |
| 文字入口 | `Package` | 写法 | 用户可能搜索或书写出来的字面形式 |
| 主题集合 | `Shelf` | 集盒/盒子 | 按主题组织义项或罐头，代码暂不改名 |

代码命名保持 `Can / Nameplate / Flavor / Package / Shelf` 稳定。不要回退到旧系统的 `Word/List` 命名，也不要因为品牌文案变化频繁迁移模型、API 或路由。

## 2. 核心模型关系

固定关系：

```text
Can 1 - N Nameplate
Nameplate -> Flavor
Nameplate -> Package
Flavor N - N Package
Shelf N - N Flavor / Can
```

`Flavor` 负责义项，例如“月亮”“银行机构”“行走动作”。它让用户可以快速检索“全国各地方言里月亮怎么说”。

`Package` 负责写法入口，例如“行”“杀”“刣”“月光”“月娘”。它让用户搜索同一个字面形式时，能够看到不同义项。

`Nameplate` 是具体到某条录音的用户主张。它同时指向一个 `Flavor` 和一个 `Package`，并保存释义、证据来源、权重和是否主铭牌。

示例：

```text
Flavor「月亮」
├─ Package「月亮」
├─ Package「月光」
├─ Package「月娘」
└─ 通过 Nameplate 连接到全国各地方言录音 Can
```

```text
Can #1 某地方言录音
├─ Nameplate A：Package「杀」 + Flavor「宰杀」 + 注解甲
├─ Nameplate B：Package「刣」 + Flavor「宰杀」 + 注解乙
└─ Nameplate C：Package「杀」 + Flavor「打/伤害」 + 注解丙
```

首期暂不解决 `Flavor` 标准化难题，只允许人工创建/选择义项。后续再做合并建议、同义归并、AI 推荐和管理员审核。

## 3. 旧系统参考与迁移原则

旧仓库是参考源，不作为运行时依赖引入：

- `hinghwa-dict-uni-app/src/pages/search.vue`：搜索页、搜索历史、搜索类型切换。
- `hinghwa-dict-uni-app/src/pages/words`：词条详情、发音列表、词典页面结构。
- `hinghwa-dict-uni-app/src/services/word.js`：旧词条搜索和批量获取 service。
- `hinghwa-dict-uni-app/src/utils/audio.js`：旧音频播放提示和错误处理。
- `hinghwa-dict-backend/hinghwa-dict-backend/word`：旧 `Word / Pronunciation / Character / List / Application` 模型与接口。
- `hinghwa-dict-backend/hinghwa-dict-backend/user`：旧用户、登录、资料逻辑。
- `hinghwa-dict-web/src/views/SearchResult.vue`：桌面端搜索结果组织。
- `hinghwa-dict-web/src/views/Words`：桌面端词条详情展示。

旧模型到新模型的映射：

| 旧系统 | 新系统 | 迁移说明 |
| --- | --- | --- |
| `Word` | `Flavor + Package + Nameplate` | 旧词条里“字面词形”和“义项”混在一起，新系统拆开 |
| `Pronunciation` | `Can + FlavorVariant` | 旧发音成为录音罐头，并可挂到某个义项变体 |
| `List` | `Shelf` | 旧词单迁移为主题集盒 |
| `Application` | 后续审核/修订申请 | 首期不恢复完整申请系统，只保留治理参考 |
| `Character` | 材料/检索参考 | 单字不作为新系统核心一等实体 |

迁移时可以借鉴旧字段、边界处理和交互，但必须按当前 Vue3/Vite/DRF 与新模型重新实现。

## 4. 核心页面与首期范围

### 首页

- 品牌展示“乡声集盒”。
- 主要入口：搜索、集盒、装罐、图鉴、我的。
- 最近罐头列表按时间倒序展示，卡片显示主铭牌写法、义项/普通话概念、方言点、铭牌数和状态。

### 装罐页

两种模式：

1. 自由装罐：用户填写普通话概念、方言点、录音，可选候选写法、释义、写法类型、来源说明。
2. 为已有义项补录音：从 `Flavor` 详情进入，锁定义项，只选择方言点并录音，提交后仍创建 `Can`。

自由装罐的必填项为普通话概念、方言点、录音。不会写正字也可以先提交，后续由社区贴铭牌。

### 罐头详情页

- 主要区展示主铭牌、普通话概念、方言点、录音者和播放按钮。
- 铭牌区展示所有用户主张；支持数最高的铭牌成为主铭牌。
- 同一录音可以有多个铭牌；写法相同但释义、义项或来源不同，也可以作为不同铭牌存在。

### 图鉴与义项详情

- 图鉴按 `Flavor` 组织，展示“同一个意思在不同地方怎么说”。
- 义项详情显示关联写法、方言变体、相关罐头。
- 例如 `Flavor=月亮` 可以检索全国各地方言里的月亮说法。

### 写法详情

- 写法详情按 `Package` 组织，展示一个写法可能关联的多个义项。
- 例如 `Package=行` 下区分“银行机构”“行走动作”“可以/好”等义项。

### 集盒

- 集盒是主题集合，内部仍使用 `Shelf`。
- 用户界面优先使用“集盒/盒子”，减少“货架”意象。
- 集盒可以收纳义项或罐头。

### 搜索

首期先实现传统单框搜索，聚合义项、写法、罐头。搜索历史、热门搜索、实时联想可以逐步增强。

### 后续扩展

- 乡音留言：围绕罐头的轻量评论和点赞。
- 草稿箱：提交失败时保存本地草稿。
- 方言圈：圈子、加入退出、圈内罐头列表。
- 铭牌支持唯一性：每人对每张铭牌只能支持一次。
- 争议态：最高两张铭牌支持数接近时标记为 `disputed`。

## 5. 状态与边界

`Can.status` 沿用当前代码：

| 状态 | 含义 |
| --- | --- |
| `unlabeled` | 无铭牌 |
| `pending` | 已有铭牌，等待社区或管理员校验 |
| `tentative` | 社区暂定 |
| `verified` | 已认证 |
| `disputed` | 存在争议 |
| `rejected` | 已驳回 |

首期创建罐头后默认为 `unlabeled`。贴第一张铭牌后进入 `pending`。更复杂的状态流转后续由专门 issue 落地。

## 6. Issue 编写标准

每个 issue 都按“小白可执行”模板写：

1. 背景：为什么做，解决什么用户问题。
2. 目标：完成后用户能做什么。
3. 概念解释：涉及 `Can / Nameplate / Flavor / Package / Shelf` 时必须写中文别名。
4. 旧代码参考：列出旧仓库具体路径。
5. 当前代码入口：列出新仓库建议阅读文件。
6. 实现步骤：写成明确的 1、2、3，不跳步。
7. 数据/API：说明字段名、请求示例、响应示例。
8. 验收标准：用 checklist。
9. 测试方式：列具体命令和手测路径。
10. 非目标：说明本 issue 不做什么，避免越做越大。

父 issue 管方向，子 issue 管单一交付。每个子 issue 尽量控制在 0.5-2 人日。

## 7. 验收样例

首期迁移和模型关系至少覆盖三类样例：

- “月亮”：同一个义项在全国多个地方怎么说。
- “行”：同一个写法对应多个不同义项。
- “杀/刣”：同一条录音存在不同写法或不同注解的铭牌争议。
