# 兴化语记旧库账号存活规则修正

## 目标

手机号相同的账号必须合并到一个目标用户，但登录主体不能机械地由“旧库账号”或“目标库账号”固定胜出。统一按以下顺序选择：拥有 Django 后台权限（`is_staff` 或 `is_superuser`）的账号优先；管理员状态相同时，`last_login` 较新的账号优先；登录时间为空视为最早；仍相同时，旧库内部按微信绑定和来源 ID 稳定排序，旧库撞目标库时保留目标账号，避免无意义地改写已有登录身份。

## 数据流

旧库内部重复手机号先选出来源存活账号，再与目标库同手机号账号比较。若目标账号胜出，沿用现有合并行为，只汇总积分和贡献关系。若来源账号胜出，继续复用目标用户主键以保留双方既有外键关系，但将用户名、密码哈希、管理员标志、启用状态、最近登录时间及来源身份资料切换为来源存活账号；旧目标登录身份、Django session、JWT 和权限关系同时失效，防止普通账号的既有登录态在身份提升后继承管理员能力。用户名、邮箱、微信或 QQ 与第三方账号冲突时不强行覆盖，记录冲突并停止该组导入。

已完成迁移的台账需要支持幂等修复：重新运行导入时，若台账记录为 `merged_target_phone`，但按新规则应由来源管理员胜出，则在事务内校验指纹和当前目标，再执行同样的身份切换，并更新台账 metadata。当前本地库在修复前创建可恢复备份。

## 验证

测试覆盖管理员对普通账号、同级账号最近登录、空登录时间、完全并列、旧库内部重复手机号、目标库手机号冲突、第三方身份冲突、已导入台账修复和幂等重跑。`cs` 场景应保留用户名与旧密码哈希，目标用户主键和贡献关系不变，并恢复 staff/superuser 权限。
